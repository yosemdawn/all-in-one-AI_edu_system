# 第一批上线安全修复

对应上线审查报告第 1–5、11 项。未执行部署，未操作既有业务数据库。

## 已改变的行为

- 教师查询其他教师的班级详情、学生名单、作业提交列表/详情或评分接口返回 403；管理员保留跨班级管理能力。
- 学生只能读取自己有效加入班级的详情；公开列表、学生班级列表和学生班级详情不再提供入班码。学生作业详情的两个入口复用成员资格和草稿可见性校验。
- 已正式提交的内容不能另存为草稿，已人工复核的内容不能重交。提交次数持续累计，不会因草稿归零。
- 所有提交内容变更、教师评分和工具箱成绩回写采用版本条件更新。并发更新冲突返回 409，不能覆盖已经写入的教师成绩。新的人工评分追加 teacherReviewHistory。
- AI 任务包含提交 revision，并以 submissionId + revision 生成稳定任务 ID。Worker 在领取和落库时都检查版本、人工评分和允许状态；迟到、重复、旧版本及旧 Worker 的结果不能覆盖当前结果。错误结果也受同样保护。
- 新写入的提交、作业说明/材料、教师与 AI 评语经过 HTML 白名单清洗；前端所有原 v-html 入口改为统一安全指令，Markdown 转换后的 HTML 和历史记录同样清洗。编辑器载入历史内容也经过清洗。
- mustChangePassword 由后端守卫强制执行，只放行个人资料读取、改密及退出相关接口；刷新令牌不能绕过。前端直接进入改密页面，不会先加载被禁止的业务菜单。改密成功后回到登录页，使用新密码登录。
- 批量导入缺省密码、管理员默认重置密码改为独立随机密码。导入结果提供下载初始密码按钮；管理员指定密码及管理端改密仍要求用户首次修改。用户不能把旧密码原样当作新密码完成激活。

开放教师注册仍保留为现有产品行为，修复后的数据隔离不依赖关闭注册。

## 更新现有环境时的注意事项

1. 前后端需要配套发布并刷新旧页面：教师评分请求现在必须携带详情接口返回的 revision；旧页面或外部调用方缺少该字段会收到 400，版本过期会收到 409。
2. 已有文档缺少 revision 时按版本 0 兼容，不需要清空数据库。新内容变更或人工评分会创建并递增版本。
3. 发布前停止旧 Worker，避免新旧代码混跑。没有 revision 的旧队列任务不会被直接执行；仍属于旧版且尚未人工确认的记录会标记 AI 失败，交教师人工复核。升级前宜先处理或排空旧队列，不要把旧任务任意标为当前版本重新投递。
4. 已经被旧缺陷清除的成绩不会凭空恢复；需要从备份或教师记录核实。已有人工评分不会被批量改写，新的评分历史从此次修复之后开始追加。
5. 未批量重置现有用户密码；已有 mustChangePassword=true 的账号现在真正受到后端限制。新导入的随机初始密码仅在该次结果中提供下载，关闭前应保存并通过既有渠道分发。
6. 富文本保留段落、加粗、列表、表格、链接等允许的内容；移除内联样式、事件属性、嵌入页面及 SVG 等内容。原始历史数据库没有执行批量迁移，显示端负责对旧内容清洗。

本次未处理原审查中的数据库端口暴露、上传持久化、普通接口限流、完整队列故障补偿、备份监控等其他上线事项；真实 Redis、真实 AI 和生产 MongoDB 7 环境仍需预发布验证。
